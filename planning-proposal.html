기획안 · Planning Proposal

학교 행사를 발표용 전체 화면 슬라이드로 알리는 사이트 구축 기획안

행사 포스터·사진을 발표 자료처럼 전체 화면 슬라이드로 띄우고, 정해진 간격으로 자동 전환하며 상시 반복 재생한다. 로비·복도의 디스플레이와 웹에서 함께 쓰는, 특정 학교에 종속되지 않는 범용 템플릿이다.

01 — Overview

개요

배경

학교의 행사·공지는 가정통신문, 문자, 여러 SNS 계정, 홈페이지 게시판으로 흩어져 있다. 복도·현관의 게시판이나 모니터는 종이 포스터를 붙이거나 담당자가 파일을 수동으로 띄우는 방식이라 최신 상태를 유지하기 어렵다. 열람자는 "지금 무엇이 중요하고 무엇이 임박했는지"를 한눈에 파악하기 어렵다.

목적

행사 포스터·현장 사진을 발표 자료 같은 전체 화면 슬라이드로 만들어, 정해진 간격으로 자동 전환하며 마지막 슬라이드에서 처음으로 끝없이 반복(상시 재생)한다. 같은 콘텐츠를 (1) 로비·복도 디스플레이(발표) 모드와 (2) 학생·학부모가 보는 웹 모드 두 형태로 내보낸다. 열람은 로그인 없이, 등록·예약·만료는 지정된 담당자만 한다.

한 줄 정의

행사 이미지를 우선순위가 매겨진 전체 화면 슬라이드쇼로 편성해, 자동 전환·무한 반복으로 상시 재생하고 디스플레이와 웹에서 함께 쓰는 반응형 알림 사이트 템플릿.

범용 템플릿 전제

  • 특정 학교에 종속되지 않는다. 학교명·로고·브랜드 색·카테고리·문의처를 설정 파일 한 곳에서 교체한다.
  • 초·중·고·대학, 학년부·학생회·동아리 등 운영 주체와 무관하게 재사용할 수 있어야 한다.
  • 브랜딩 교체와 디스플레이 연결까지 반나절 이내에 끝나는 것을 배포 목표로 한다.

02 — Problem

문제 정의

현행 채널은 저마다 다음 한계를 갖는다. 이 사이트는 그 공백, 즉 "중요도·시점 순으로 정렬된 큰 이미지 노출 + 무인 자동 운영 + 무로그인 즉시 열람"을 메운다.

채널한계
종이 포스터 / 게시판부착·교체가 수작업이고 지난 것이 그대로 남는다. 원격에서 갱신 불가.
디스플레이에 파일 직접 재생담당자가 PC에서 파일을 열어 둬야 하고, 순서·만료 관리가 안 된다.
학교 홈페이지 게시판시간순 정렬이라 중요 공지가 묻히고, 이미지가 작게 첨부로만 붙는다.
문자 / SNS이미지 화질·노출이 채널에 좌우되고, 지난 공지 히스토리를 한곳에서 보기 어렵다.

→ 필요한 것: 큰 이미지 중심의 첫 화면, 중요도·시점 자동 정렬, 무인 연속 구동, 로그인 없는 즉시 열람.

03 — Goals & Metrics

목표 · 성공 지표

목표

  • G1. 디스플레이·웹 모두에서, 3초 안에 "가장 중요한 행사 1건"을 큰 이미지와 제목으로 인지한다.
  • G2. 담당자가 이미지 1장을 올려 공지 1건을 등록·예약하는 데 5분 이내가 걸린다.
  • G3. 디스플레이 모드가 사람 손 없이 24시간 이상 연속 구동되며 콘텐츠를 자동 갱신한다.
  • G4. 새 학교 배포(브랜딩 교체 → 디스플레이 연결 → 첫 게시)를 반나절 안에 마친다.

04 — Users & Contexts

사용자 · 이용 상황

디스플레이 앞 열람자 — 지나가는 학생 · 방문자

복도·현관을 지나며 몇 초간 본다. 조작하지 않는다. 멀리서도 읽히는 큰 이미지와 짧은 제목, 날짜/D-day가 핵심. 슬라이드는 천천히(8~10초) 넘어가야 한다.

웹 열람자 — 학생 · 학부모 · 교직원

주로 모바일. 전체 화면 슬라이드에서 관심 있는 행사를 탭해 상세(일정·장소·준비물·우천 시 대응)를 확인한다. 아래로 스크롤하면 전체 목록으로 이어진다.

운영자 — 담당 교사 · 행정실 · 학생회 담당

1~5명. 이미지를 올리고 크롭·포커스 포인트를 지정한 뒤 티어·게시 기간만 정하면 끝나야 한다. 예약 게시와 자동 만료는 필수 — 지난 행사가 화면에 남지 않도록 한다.

배포자 — 초기 구축 담당 / 외주

설정 파일과 환경변수로 브랜딩·카테고리를 정의하고, 디스플레이 PC/TV 브라우저를 /display 주소로 고정한다.

05 — Scope

범위 (포함 / 제외)

이번 범위에 포함

  • 전체 화면 이미지 슬라이드 — 우선순위 정렬, 고정 핀, 자동 순환, 페이드/슬라이드 전환
  • 디스플레이(키오스크) 모드 — 크롬 없는 전체 화면, 자동 콘텐츠 갱신, 화면 꺼짐 방지
  • 웹 모드 — 전체 화면 히어로 슬라이드 + 좌우·인디케이터·스와이프 조작, 탭 시 상세
  • 이미지 업로드 → 자동 리사이즈·포맷 변환(AVIF/WebP/JPEG) → 반응형 srcset
  • 크롭 미리보기 + 포커스 포인트 지정, 가로·세로 디스플레이 대응
  • 가독성 스크림 자동 적용, 이미지가 없을 때 브랜드 배경 + 타이포 대체
  • 3단계 중요도 티어 — 긴급 / 중요 / 일반 (색 + 아이콘 + 라벨)
  • 행사 상세 페이지 — 본문, 일정, 장소, 첨부 링크, 우천·비상 시 대응
  • 전체 목록 페이지 — 카테고리·기간 필터, 제목 검색
  • 관리자 — 등록 / 수정 / 삭제, 예약 게시, 자동 만료, 미리보기
  • 반응형 · 다크 모드 · 접근성 WCAG 2.1 AA 목표 (alt 텍스트 필수)
  • 브랜딩 설정 1파일, 상세 페이지 .ics 내보내기

이번 범위에서 제외 → 10. 로드맵 참고

  • 동영상 슬라이드, 여러 디스플레이의 중앙 관리 콘솔
  • 행사 신청·설문·참석 체크
  • 이메일 / 웹푸시 알림 발송
  • 구글·네이버 캘린더 양방향 연동
  • 다국어(i18n) — 문구 상수화 준비까지만
  • 사용자 계정·권한 세분화 — 관리자 단일 역할만
  • 통계 대시보드 — 외부 분석 도구로 대체

06 — Features

기능 명세

우선순위: P0 출시 필수 · P1 출시 직후 · P2 이후 개선.

기능설명우선순위
발표형 전체 화면 슬라이드쇼 이미지가 뷰포트를 꽉 채움(object-fit: cover). 티어·게시 시작일 순으로 편성, 슬라이드당 표시 시간 후 자동 전환, 마지막 → 처음 무한 반복. P0
전환 효과 & 진행 표시 전환 방식(페이드 / 슬라이드 / 없음)과 슬라이드당 시간(기본 10초)을 설정에서 지정. 상단 진행 바 + "n / 전체" 카운터로 다음 전환까지 표시. P0
이미지 업로드 & 자동 최적화 원본 보관 + 다중 크기 생성(640·1280·1920·2560), AVIF·WebP·JPEG 폴백, srcset·sizes 자동. P0
가독성 스크림 & 텍스트 오버레이 하단 그라디언트 스크림 자동. 밝은 이미지에서도 대비 4.5:1 확보, 미달 시 하단 솔리드 바로 폴백. P0
디스플레이(발표) 모드 · 상시 재생 /display 전용 라우트. 크롬·조작 UI 없이 슬라이드쇼만 무한 반복. N분마다 콘텐츠 자동 갱신, Screen Wake Lock, 멈춤 감지 시 자동 새로고침. P0
중요도 티어 긴급(빨강)·중요(주황)·일반(파랑)을 색 + 아이콘 + 라벨 3중 표기. 티어 색은 브랜드 색과 분리. P0
고정 핀 (pin) 회전과 무관하게 항상 첫 슬라이드로 노출. 동시 1건 권장, 2건 이상이면 관리자에 경고. P0
예약 게시 & 자동 만료 게시 시작/종료 일시 지정. 종료 후 슬라이드·목록 상단에서 자동 제외, 목록엔 '지난 행사'로 잔류. P0
상세 페이지 + 관리자 등록 폼 제목·기간·장소·본문·첨부·문의처·대응 안내. 필수: 이미지·alt·제목·티어·게시 기간. 저장 전 미리보기. P0
크롭 미리보기 & 포커스 포인트 업로드 후 관리자가 크롭 프레임·초점을 지정. 가로/세로 뷰포트별 잘림을 미리 확인. P1
이미지 없을 때 대체 브랜드 배경 + 대형 타이포 + 카테고리 아이콘으로 자동 구성. P1
세로(포트레이트) 디스플레이 대응 세로 방향 감지 시 세로용 대체 이미지 사용, 없으면 초점 기준 세로 크롭. P1
웹 슬라이드 조작 & 접근성 좌우 버튼·인디케이터·스와이프, 키보드 전체 조작, prefers-reduced-motion 시 페이드/즉시 전환, 오버·포커스 시 정지. P1
카테고리·기간 필터 / 전체 목록 칩 토글(URL 쿼리 반영), 제목 검색, 페이지네이션. P1
.ics 내보내기 상세 페이지 "내 캘린더에 추가"로 행사 1건 다운로드. P1
경량 클릭·노출 로깅 / 임시저장 / RSS·JSON 피드 배너 노출·클릭 카운트, 초안 보관, 타 시스템 연계용 피드. P2

슬라이드쇼 편성 · 재생 규칙

  • 편성 순서: 고정 핀 → 티어(긴급 > 중요 > 일반) → 게시 시작일 오름차순 → 등록일.
  • 재생: 슬라이드당 표시 시간(설정, 기본 10초) 경과 시 다음으로 전환, 마지막에서 첫 슬라이드로 끊김 없이 순환(상시 반복).
  • 진행 표시: 상단 진행 바가 남은 시간을, 하단 인디케이터가 "현재 / 전체"를 표시.
  • 이미지: 뷰포트를 꽉 채우고 포커스 포인트 기준 크롭. 로드 전 저해상도 블러 또는 브랜드 색 자리표시.
  • 텍스트: 하단 정렬. 카테고리 칩 · 티어 · 제목(최대 2줄) · 날짜/D-day. 디스플레이 모드는 글자 크기를 키운다.
  • 전환 효과: 페이드 / 슬라이드 / 없음 중 설정. prefers-reduced-motion 시 페이드 또는 즉시.
  • 조작: 웹만 좌우·인디케이터·스와이프, 오버·포커스 시 정지. 디스플레이 모드는 자동 전환·반복만.
  • 단일 항목: 슬라이드가 1건이면 정적 표시(전환 없음).
  • 콘텐츠 갱신: 재생 중 N분마다 최신 편성을 받아 현재 슬라이드가 끝난 뒤 자연스럽게 교체.

중요주황 + 별표 아이콘 + "중요"일정·준비물이 걸린 주요 행사 (체육대회, 축제, 시험, 현장학습)긴급 다음 순서
일반파랑 + 정보 아이콘 + "일반"참고성 안내 (개방 시간 변경, 신청 접수, 동아리 모집)회전 후순위

공지 상태 흐름

초안 → 예약 → 게시 중 → 만료 → 보관

예약·게시 중·만료는 startAt / endAt으로 자동 판정된다. 초안과 보관만 관리자가 수동으로 지정한다.

09 — Tech Stack & Image Pipeline

기술 스택 · 이미지 파이프라인

공통 원칙: 정적 우선, 산출물은 CDN 배포, 런타임 의존성 최소화, 서버 상시 운영 없이도 동작. 슬라이드 정렬·순환·필터 로직은 프레임워크에 비종속인 순수 JS 모듈로 분리해 재사용한다.

옵션구성이미지 처리적합 대상
A. 정적 + JSON 파일 SSG(Astro · Eleventy) + 저장소의 events.json · 이미지 빌드 시 이미지 변환(sharp / Astro Image) 개발자 1인이 관리하거나 공지 빈도가 낮은 곳. 비용 0, 비개발자 등록은 불편
B. 정적 + 헤드리스 CMS 권장 SSG + Sanity · Decap, 빌드 웹훅으로 재배포 Sanity는 이미지 CDN·크롭·포커스 내장 / Decap은 Netlify Image CDN 등 별도 연결 담당 교사가 직접 이미지 업로드·크롭. 범용 배포에 가장 적합
C. 풀스택 경량 Next.js + DB + 자체 관리자, next/image 또는 이미지 CDN 요청 시 온디맨드 리사이즈 로깅·초안·피드까지 자체 제어가 필요하고 유지보수 인력이 있을 때

권장

옵션 B (SSG + Sanity). 비개발자가 이미지를 올리고 크롭·포커스를 지정할 수 있고, 이미지 CDN이 다중 크기·포맷을 자동 제공한다. 예약·만료는 "빌드 시점 필터 + 하루 1회 정기 재빌드 + 디스플레이 모드의 N분 폴링"으로 충분하다. 서버 상시 운영 부담이 없다.

디스플레이(발표) 모드 · 상시 반복 구현

  • 상시 재생: requestAnimationFrame 기반 타이머로 슬라이드당 시간 경과 시 인덱스를 (i + 1) % n으로 순환. 탭 백그라운드 후 복귀해도 타이머·진행 바가 어긋나지 않게 보정.
  • 전환: 두 레이어 교차 페이드(또는 translate) + 다음 이미지 미리 디코드로 깜빡임 방지.
  • 콘텐츠 갱신: /display가 N분(기본 5분)마다 편성 JSON을 폴링해 현재 슬라이드가 끝난 뒤 교체. 실패 시 마지막 캐시 유지.
  • 화면 유지: Screen Wake Lock API로 절전 방지, 가시성 복귀 시 즉시 재동기화.
  • 안정성: 프런트 워치독(멈춤·에러 감지 시 자동 새로고침), 오프라인 배지, 브라우저 전체 화면·자동 실행은 배포 가이드로 안내.
  • 방향: 설정 display.orientation으로 가로/세로 지정, 세로 시 imagePortrait 사용.

부가 기준

  • 호스팅: Netlify · Vercel · Cloudflare Pages · 학교 자체 정적 호스팅 중 택1.
  • 성능: 이미지 지연 로딩(첫 슬라이드 preload), 폰트 서브셋, 슬라이드 로직 외 JS 번들 < 35KB(gzip) 목표.
  • 접근성: alt 텍스트 필수화, 스크림 대비 자동 검사, 키보드·스크린리더 점검을 릴리스 체크리스트에 포함.
